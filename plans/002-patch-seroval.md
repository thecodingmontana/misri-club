## Why this matters

`seroval` is the library TanStack Router uses to serialize loader data into the
server-rendered HTML of every page. The lockfile pins `seroval@1.6.9`, which has
two moderate advisories: GHSA-9wx9-5pv9-3349 (script injection through RegExp
sources, fixed in 1.6.10) and a code-injection issue through a typed array's
`constructor` property (fixed in 1.6.11). It runs on every page, not only in
tooling. The fix is a version bump inside the range TanStack already allows
(`@tanstack/router-core` declares `seroval: ^1.6.7`; the latest release is 1.8.1).

## Current state

## Steps

### Step 1: Try the in-range update first

From the repo root run `pnpm update seroval --recursive --depth Infinity`.

**Verify**: `grep -oE "seroval@[0-9.]+" pnpm-lock.yaml | sort -u` → a single
version ≥ `1.6.11`. If so, skip Step 2.

### Step 2 (only if Step 1 left 1.6.9): add an override

Append to `pnpm-workspace.yaml`:

```yaml
# seroval < 1.6.11 has injection advisories (GHSA-9wx9-5pv9-3349 and the
# typed-array constructor one); TanStack allows ^1.6.7, so force the patch.
overrides:
  seroval: ^1.6.11
```

Then run `pnpm install`.

**Verify**: same grep → a single version ≥ `1.6.11`.

### Step 3: Confirm nothing regressed

Run `pnpm audit --recursive`, `pnpm test`, and the build from the table above.

**Verify**: audit output contains no row whose Package is `seroval`; tests
print `ℹ fail 0`; the build prints `✓ built`.
